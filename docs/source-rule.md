# 书源规则

在小程序「我的 → 书源管理 → 新增书源」里有三种办法添加书源：

1. **填名称和地址（简单模式）**：只填书源名称、网站首页地址和类型，其余全部自动识别，见下面的「自动识别」。
2. **导入 JSON 规则（高级模式）**：自动识别不了的网站，按本文的格式写规则（可以让 AI 对着网页写），粘贴一个 JSON 对象或一个 JSON 数组（一次导入多个）。
3. **订阅书源列表**：填一个 JSON 文件的网址，见下面的「订阅」。

保存前可以在编辑页点「测试」，后端会依次执行搜索、详情、目录、第一章正文并返回结果，不会写入数据库。简单模式下关键词可以不填，这时从首页取一本书来试。

## 自动识别

规则里的值写成 `auto`，或者干脆不写，就由后端按页面结构识别。只有 `name`、`type`、`baseUrl` 的书源等于全部 `auto`：

```json
{ "name": "某站", "type": "novel", "baseUrl": "https://example.com" }
```

识别的办法：

| 部分 | 怎么识别 |
| --- | --- |
| 搜索地址 | 首页上带文本输入框的表单（GET 或 POST，隐藏字段一并带上）；首页没有表单时，跟着「搜索」链接到搜索页再找 |
| 搜索结果 / 首页书单 | 页面上同一种地址的一组链接（数字段视为相同）；有关键词时取书名含关键词的那一组 |
| 书籍详情 | `og:` 系列 meta 标签，其次是唯一的 `h1`、带「作者」字样的文字、类名含 intro / desc 的元素 |
| 目录 | 最大的一组章节链接；最新章节的重复块会去掉，倒序的会正过来，分页的会翻完 |
| 小说正文 | 文字最多的那个元素，去掉其中的脚本、链接和表单；分成几页的章节会接起来 |
| 漫画图片 | 连续的一组图片（懒加载属性 `data-src`、`data-original` 等优先），其次是脚本里列出的图片地址。页面上另有一组更多的图片（如一排推广图）时可能认错，这时请写明 `images` 规则 |

可以只让一部分自动：写了的规则照规则执行，没写的 `search`、`toc`、`content` 自动识别。例如只指定搜索地址：

```json
{ "name": "某站", "type": "novel", "baseUrl": "https://example.com", "search": { "url": "/s?wd={{key}}" } }
```

自动识别只读普通的网页（HTML）。下面这些识别不了，测试时会说明是哪一步，需要改写规则：

- 内容由脚本加载，或接口返回的是 JSON
- 页面结构不常规（比如搜索结果和别的书单用同一种链接、又不含关键词）
- 需要登录、验证码或人机验证的网站：不会也不应绕过，见文末

## 订阅

「订阅书源列表」填一个网址，后端下载它并导入其中的书源，之后可以在书源管理页点「同步」或「全部同步」按列表更新。

- 文件内容可以是单个书源对象、书源数组、包含 `sources` 数组的源包对象（`{"sources":[...]}`），或不含 JS 脚本的声明式「阅读（Legado）」书源 JSON。文件大小不限（服务器边下载边解析），单个书源不超过 1 MB。
- GitHub、Gist、Gitee、GitLab 上的文件可以直接填页面地址（如 `https://github.com/<用户>/<仓库>/blob/<分支>/<文件>`、`https://gitee.com/<用户>/<仓库>/blob/<分支>/<文件>`），后端会自动转换为 Raw 地址。私有仓库读不到。
- 如果希望从自己的服务器直接对外提供订阅链接，可在后端设置环境变量 `SOURCES_FEED_FILE=/path/to/sources.json`，启动后即通过 `GET /api/sources/feed.json` 提供只读订阅地址；也可设置 `SEED_SOURCES_FILE` 在启动时自动导入本地书源文件。
- 同步时，名称和类型相同的书源原地更新；列表里删掉的书源**不会**被删除（否则它的书架和历史也会一起删掉），需要的话手动删。
- 列表里格式不对或包含 JS 脚本的条目会跳过并在同步结果里列出来。
- 取消订阅时可以选择保留或一并删除它导入的书源。
- 列表和它带来的书源都只从公网地址读取，后端直接连接、不经代理；指向服务器本机或内网的地址会被拒绝。取消订阅后保留下来的书源、以及之后手工改过的这类书源也一样。需要读内网站点的书源请自己在书源管理里新增。
- 列表里的书源和已有的同名书源重复时，更新的是这份订阅上次导入的那一个。

## 数据源监听

后端会自动监听所有书源的搜索、推荐、详情、目录、正文/图集和图片抓取，并将统计持久化保存在 SQLite（`source_metrics` 表）：

- **响应时间**：平均响应时间、最近响应时间、最小/最大响应时间，以及近 100 次请求的 P95 响应时间（毫秒）。
- **有效/无效内容比率**：有效内容次数（返回非空书籍/目录/正文/图片）、无效内容次数（拆分为空结果 `empty` 与报错 `error`）、有效率与无效率，以及分动作明细。
- 可通过 `GET /api/sources/metrics` 查看总览和各源详情，通过 `POST /api/sources/monitor/check` 主动拨测（可带 `?id=` 或 `?type=`），通过 `DELETE /api/sources/:id/metrics` 重置单源统计。

本项目不提供任何书源列表。请只订阅你自己维护的、或有权使用其内容的列表。

## 规则字符串

每个规则字段都是一个字符串：

```
[类型:]表达式[@属性][##正则[##替换]]
```

| 类型 | 例子 | 说明 |
|---|---|---|
| `css:` | `css:.list li a@href` | CSS 选择器。`@属性` 可以是 `text`（默认）、`html`、`outerHtml` 或任意 HTML 属性 |
| `xpath:` | `xpath://div[@id="x"]//a/@href` | XPath |
| `json:` | `json:data.list.#.name` | [gjson](https://github.com/tidwall/gjson) 路径。响应是 JSON 时可以省略 `json:` 前缀 |
| `regex:` | `regex:var url = "(.*?)"` | 取每个匹配的第一个捕获组 |

- 列表（`list`）下面的字段规则是相对每个列表项求值的。表达式留空表示列表项本身，例如 `@href`、`@text`。
- `##正则##替换` 对取到的值做替换，省略替换就是删除。例如 `css:.author##^作者：` 去掉前缀，`id##^##book/` 在前面加上 `book/`。替换里用 `${1}` 引用捕获组。
- 可以接多组 `##正则##替换`，按顺序依次执行，例如列表页没有封面、但封面地址能从书的地址换算出来时：`css:a@href##^.*/(\d+)/(\d+)\.html$##/image/${1}/${2}/${2}s.jpg`。
- 取到的链接如果是相对地址，会按所在页面的地址补全。

## 字段

```jsonc
{
  "name": "某站",                 // 必填
  "type": "novel",                // 必填，novel 或 comic
  "baseUrl": "https://example.com", // 必填
  "headers": { "User-Agent": "...", "Referer": "..." }, // 可选，抓页面和图片时都会带上
  "charset": "gbk",               // 可选，留空自动识别；填了之后搜索词也按这个编码发送
  "rateLimitMs": 500,             // 可选，对该站两次请求的最小间隔

  "search": {
    "url": "/search?q={{key}}&page={{page}}", // 必填，相对 baseUrl 或完整地址
    "method": "POST",             // 可选，默认 GET
    "body": "keyword={{key}}",    // 可选，POST 的请求体
    "list": "css:.result li",     // 必填，每一条搜索结果
    "title": "css:a",             // 必填
    "bookUrl": "css:a@href",      // 必填，书籍详情页地址
    "author": "", "cover": "", "intro": "", "latest": "" // 可选
  },

  "recommend": {                  // 可选，整段不写就没有推荐；字段和 search 相同
    "url": "/rank",               // 必填，站点的排行榜、首页等任意一个书籍列表页
    "list": "css:.rank li",       // 必填
    "title": "css:a",             // 必填
    "bookUrl": "css:a@href",      // 必填
    "author": "", "cover": "", "intro": "", "latest": "" // 可选
  },

  "detail": {                     // 都是可选的，取到了就覆盖搜索结果里的值
    "title": "", "author": "", "cover": "", "intro": "", "latest": "",
    "tocUrl": ""                  // 目录页地址；留空表示目录就在详情页
  },

  "toc": {
    "list": "css:#list dd a",     // 必填，每一章
    "name": "@text",
    "url": "@href",               // 必填
    "nextPage": "",               // 可选，目录分页的下一页地址
    "reverse": false,             // 可选，站点目录是倒序时设为 true
    "fallback": null              // 可选，另一组 list / name / url / reverse；上面的规则一章都没找到时改用它
  },

  "content": {
    "body": "css:#content",       // 小说源必填，正文
    "images": "",                 // 漫画源必填，图片地址列表
    "nextPage": "",               // 可选，一章分多页时的下一页地址
    "purify": ["请记住本站域名.*"] // 可选，从正文里删除的正则
  }
}
```

`content.nextPage` 会一直跟到取不到地址、地址重复，或者到达下一章的地址为止。

## 推荐和排行

搜索页在没有输入关键词时，用每个书源的 `recommend` 列表（每个书源最多取前 100 本）做两个视图。列表在后端缓存 30 分钟；站点读不到时继续用上一次的结果，5 分钟后再重试。

**排行**：选一个书源，按站点列表原来的顺序显示。

**推荐**：把当前模式下所有书源的列表合并成一份：

1. **去重**：书名和作者去掉空格、标点、大小写后比较。书名相同且作者相同（或有一方没有作者）算同一本，只出现一次；展示有封面的那一份，都有或都没有时取名次靠前的。
2. **排除已读**：书架和历史里已有的书名不再推荐。
3. **打分**：一本书在某个书源排第 n 名得 `1 / (10 + n)` 分，各书源的得分相加。所以多个书源同时上榜的书，会排在只有一个书源排第一的书前面。
4. **偏好**：作者在书架或历史里出现过的书，得分 ×1.5；有封面的书 ×1.1。
5. **每日变化**：得分再乘一个 ±15% 以内的系数，由「用户、日期、书名」算出，同一天内顺序固定（翻页不会错位），第二天略有不同。
6. **书源穿插**：按得分从高到低取，如果和上一本是同一个书源，就在后面 5 本里找一本别的书源的先放。

卡片上的标签：「N 个书源上榜」或「读过这位作者」。

目录最多跟 100 页，一章正文最多跟 30 页，超过会直接报错，不会返回不完整的结果。

## 例子

HTML 小说站：

```json
{
  "name": "演示小说源",
  "type": "novel",
  "baseUrl": "http://127.0.0.1:8080/demo/novel",
  "search": {
    "url": "/search?q={{key}}&page={{page}}",
    "list": "css:.result li",
    "title": "css:a.name",
    "bookUrl": "css:a.name@href",
    "author": "css:.author",
    "cover": "css:img@src",
    "intro": "css:.intro"
  },
  "detail": {
    "title": "css:#info h1",
    "author": "css:#info .author##^作者：",
    "cover": "css:#cover@src",
    "intro": "css:#intro"
  },
  "toc": { "list": "css:#list dd a", "name": "@text", "url": "@href" },
  "content": {
    "body": "css:#content",
    "nextPage": "xpath://a[@id='next']/@href",
    "purify": ["请记住本站域名.*"]
  }
}
```

JSON 接口的漫画站：

```json
{
  "name": "演示漫画源",
  "type": "comic",
  "baseUrl": "http://127.0.0.1:8080/demo/comic",
  "search": {
    "url": "/api/search?q={{key}}",
    "list": "json:data.list",
    "title": "name",
    "bookUrl": "id##^##book/",
    "author": "author",
    "cover": "cover",
    "intro": "desc"
  },
  "detail": { "title": "data.name", "author": "data.author", "cover": "data.cover", "intro": "data.desc" },
  "toc": { "list": "data.chapters", "name": "name", "url": "path", "reverse": true },
  "content": { "images": "data.images" }
}
```

这两个就是 `DEMO_SOURCE=true` 时后端自带的演示书源，对应的假站点代码在 `server/internal/demo/demo.go`。

## 导入和更新

导入时，名称和类型都与已有书源相同的规则会直接更新那个书源（书架、历史保留），所以规则有改动时重新导入即可，不要先删除旧书源（删除书源会连同它的书架和历史一起删除）。

本仓库不提供、也不收录任何指向第三方站点的书源规则。书源由使用者自行编写和配置，请只接入你有权访问和使用的内容来源，并遵守该站点的服务条款和 robots 协议。

第三方站点改版后，规则失效时用 `POST /api/sources/test?q=关键词` 对照页面结构调整。

## 不支持的情况

- 需要执行 JavaScript 才能得到内容的页面
- 需要登录、验证码或人机验证的站点：规则引擎不会也不应绕过这些访问控制
